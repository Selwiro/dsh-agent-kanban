# 智能体看板

一个 DeepSeek Harness（DSH）插件：把本机各个项目的进度收进同一个页面，并且让智能体能直接接活、交活。

项目一多，进度就散在各自的文件夹里——想知道"现在该做什么"，得挨个打开翻一遍。这个插件把这些项目聚到一块看板上，任务不用复制粘贴，智能体做完会把结果写回来。

## 打开后是什么样

- **侧栏的「智能体看板」**：跨项目总览。有多少项目、各有多少待办、进行中和阻塞，以及当下最值得动手的那一件事。
- **项目页**：任务按「待办 / 进行中 / 待验收 / 阻塞」四列摆开，已完成折叠在下面，不占版面。
- **会话顶部的「看板」页**：跟着当前会话的工作区，只显示这个项目的任务。

界面中英双语。

## 三步开始

1. **装插件**：克隆本仓库，在 DSH 的 **插件 → 添加插件** 里选这个目录，安装后启用。npm 包会在正式版发布，届时可以直接填 `dsh-agent-kanban` 安装。
2. **打开看板**：点侧栏「智能体看板」。DSH 里登记过的工作区会自动扫描，里面的项目直接出现。
3. **补目录（可选）**：如果项目不在任何 DSH 工作区里，点右上角「添加工作区外目录」，选项目目录或它的父目录。扫描只往下找 4 层，认的是 `management/project.json`。

## 日常怎么用

**想知道现在做什么**，打开总览看「当前焦点」。

**想派活给智能体**，进任务详情点「在新会话执行」。看板会：

1. 在项目目录下开一个新会话；
2. 把任务标成进行中，记下会话 ID；
3. 把执行指令直接发给智能体。

不用复制、不用粘贴。智能体干完调 `kanban_finish` 提交，遇到问题调 `kanban_block` 说明原因。

**验收**：任务不会自己变成「已完成」，会先停在「待验收」。你点「通过验收」才算完，点「退回重做」它会重新进入执行。看板每 5 秒刷新一次，智能体那边有动静这边很快能看到。

**也可以手动来**：新建任务、开始、完成、标记阻塞都能直接点；「复制指令」适合把任务交给已经有会话的智能体。

## 配合 project-initializer skill

看板只负责「看见」和「派发」。项目怎么建目录、需求怎么登记、什么时候算结项，交给 **[project-initializer](https://github.com/Selwiro/project-initializer)** skill 更合适。两者读写同一套 `management/` 文件，接上之后是一条完整的链路：

1. **接入**：让智能体用 skill 初始化或接入项目，看板下次扫描就能看到它，不用手动添加。
2. **登记**：有新需求时用 skill 登记，需求立刻变成看板上的待办任务。
3. **执行**：从看板把任务派给会话执行；智能体做完按约定回写状态和结果。
4. **收尾**：搁置、恢复、结项、迁移都按 skill 的约定走，历史记录留在原处。

不开看板也行：skill 自带 `status`、`inspect`、`task` 命令，终端里就能查进度、核对结构、看单条任务。

> 本仓库不包含这个 skill。先在 DSH 里装好并启用 [project-initializer](https://github.com/Selwiro/project-initializer)（Python 3.9+，只用标准库），两边配合才能闭环。

## 智能体能用的工具

| 工具 | 做什么 |
| --- | --- |
| `kanban_projects` | 看有哪些项目、各自进度、下一项是什么 |
| `kanban_show` | 读一条任务的详情和验收条件 |
| `kanban_create` | 新建待办任务 |
| `kanban_start` | 开工，拿到 `run_id` |
| `kanban_finish` | 交活并提交验收 |
| `kanban_block` | 说明卡在哪、什么条件下能继续 |

## 数据和隐私

- 只读写项目自己的 `management/project.json` 和 `management/tasks/*.md`，别的不碰。
- 扫描来源只有两个：DSH 登记的工作区，和你手动添加的外部目录（记在 `~/.dsh/agent-kanban/roots.json`）。
- 不联网、不上报、不收集遥测。接口是挂在 DSH 自己 Web 服务下的 `/api/kanban`，只接受本页面发来的请求，不另开端口。
- 写文件用临时文件原子替换，同一进程内按项目排队，不会写花。
- 有些项目会自动变成只读：任务由外部系统维护、项目已结项、索引在根目录、或者目录本身没写权限。界面会写清楚原因。

## 设置

一般不用改。确有需要，可以在插件配置里调：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `rootsFile` | `~/.dsh/agent-kanban/roots.json` | 外部目录登记在哪 |
| `depth` | `4` | 向下扫描几层（0–8） |
| `maxMs` | `10000` | 一次扫描最多花多久 |
| `cacheMs` | `3000` | 扫描结果缓存多久 |

## 常见问题

**项目没出现？** 先确认目录里有 `management/project.json`；项目超过 4 层深，或者目录特别大扫到 10 秒上限，也会漏。总览里会给出扫描提示。

**为什么不能改任务？** 看任务详情上方写的原因。只读通常是这几种：外部来源维护、项目已结项、索引归任务服务管、目录不可写。

**和网页版、CLI 会打架吗？** 它们共用同一套 `management/` 格式，可以混着用。但跨进程没有文件锁，别同时改同一条任务。

**要自己准备数据目录吗？** 不用特意初始化。插件只认已经存在的 `management/project.json`，没有就跳过。

## 兼容性

DSH `>= 0.2.0 < 0.3.0`，Web 平台；Node 22.19+ 或 24+（用 DSH 自带运行时即可）。

## 开发

纯 ESM，没有构建步骤。主要文件：

```
index.js          Host 入口：扫描、API、工具注册
client.js         Web 界面：总览、项目页、会话看板页
lib/              扫描解析、任务写入、HTTP 接口、工具定义
locale/           中英文案
docs/DETAIL.md    插件详情页文档
cordis.patch.yml  bundle 补丁
```

本地调试时把这个仓库目录当作「添加插件」的本地目录装上，改完重载插件即可。已知限制：扫描有 10 秒预算、刷新是 5 秒轮询而不是实时推送。
